# Key 07 — REWORK

- **Verdict:** REWORK
- **Rung:** 2 — a foreign key over data that has not been checked.
- **Failing items (all required):**
  - **4 Existing rows** — ~3% of 1.4 million comments (~42,000) are orphans. With foreign-key checks on, the `ALTER` at line 10 fails in the deploy; with them off, the constraint is added and the orphans remain, so the constraint lies.
  - **10 Proof** — the seeder writes no orphan, so the green round-trip proves nothing about this case.
- **Escalation:** clear. A data-preserving route meets the ask: record the orphans' `post_id` values (an archive table or a column), set them to `NULL` (the column is nullable), then add the constraint.
- **Acceptable fix patterns:** `clean-before-constrain` (required); `add-roundtrip-proof` seeding an orphan (required); `one-ddl-per-migration` for splitting the clean-up from the constraint (credit).
- **Wrong answers that fail the case:** GRANT. A fix that deletes orphan comments without recording them — that is a data-losing fix inside a REWORK.
